# Parity — Slice P1.1: Provenance Correction

**Scope: narrow. This is not a new feature slice — it corrects an omission in Claude's own P1 completion report, on top of the already-committed, already-externally-verified P1 slice (`d501b7602e385889267943267d2ed0fdb9a746e0`).**

## What was wrong

Claude's P1 completion report stated that TSLA and NVDA's resolved Uniswap V3 pool addresses "were not included in the operator's external report," and left `poolAddressMainnet: null` for both in `src/config/tickers.ts` on that basis. This was incorrect — the addresses were captured in the VPS live-proof output all along; Claude's own summarization of that output simply omitted them.

## What was corrected

Per the operator-supplied, externally-captured live-proof data:

| Ticker | Pool address | token0 | token1 |
|---|---|---|---|
| TSLA | `0xf4ACdAEEB7022862A763C9B1B885e11191c889E3` | TSLA (`0x322F0929c4625eD5bAd873c95208D54E1c003b2d`) | USDG (`0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168`) |
| NVDA | `0xB944cec30Bd4175855215D767ADC81F39e5f7E2B` | USDG (`0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168`) | NVDA (`0xd0601CE157Db5bdC3162BbaC2a2C8aF5320D9EEC`) |

Both token addresses match this repository's own already-committed `tokenAddressMainnet` values for TSLA and NVDA exactly, and both USDG legs match the `USDG_MAINNET` constant already used throughout the codebase (`scripts/proveP0.ts`) — full internal consistency, no new address introduced without a cross-check against something already trusted.

**Worth noting explicitly:** TSLA's pool has the Stock Token as `token0` and USDG as `token1`; NVDA's pool has the reverse. This is exactly the orientation variability `src/domain/poolPrice.ts` was built to handle without assuming either order — and it is now backed by two real, live, opposite-orientation examples rather than only the synthetic ones in `test/poolPrice.test.ts`.

`src/config/tickers.ts` now sets `poolAddressMainnet` to these exact values for TSLA and NVDA, with the provenance text for each row updated to cite them directly and to note the correction.

## What was added to prevent a recurrence

`test/tickersP1.test.ts` gained a new describe block, "Slice P1.1 — a promoted (poolVerified=true) ticker can never have a null pool address," asserting the general invariant: any row with `poolVerified: true` must have a non-null, well-formed `poolAddressMainnet`. A second test runs the same check against a deliberately-broken synthetic fixture to confirm the invariant actually fails when it should, not just when it happens to pass.
