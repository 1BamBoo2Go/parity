## Purpose

Sept. 29, 2026 is when Robinhood Chain's launch gas subsidy expires — a fixed, non-recoverable date. Data not collected before it is gone permanently. This slice adds **no new product logic and no new ticker coverage** — it schedules the exact, already-externally-verified read paths from Slices P0/P1/P1.1 and archives their output as a plain, append-only time series, so the subsidy expiration becomes a real before/after dataset instead of an anecdote.

## Storage format

Three flat JSON Lines (JSONL) files under `data/snapshots/` (gitignored — this is runtime output, not source):

- `ticker-snapshots.jsonl` — one line per ticker per run. The main time series.
- `registry-snapshots.jsonl` — one line per run: the raw `/rhj/assets` response, archived verbatim (no comparison or diffing logic — that is explicitly out of scope).
- `gas-snapshots.jsonl` — one line per run: latest block number, timestamp, and `baseFeePerGas`.

**Why JSONL, not a database:** per instruction ("avoid premature infrastructure"), and because every write is a pure append (`appendFileSync`), never a read-modify-rewrite of existing content. That is the actual mechanism — not just documentation — behind "a rerun cannot silently corrupt history": every byte written by a previous run is untouched by every subsequent one, by construction. `test/jsonlStore.test.ts` includes a regression test that literally reads the file's bytes before and after a second append and asserts the first run's content is an exact, untouched prefix.

### `ticker-snapshots.jsonl` schema (one record)

Every price/state field is a serialized `DataPoint` (`{status: "ok", value, asOf, source}` or `{status: "unavailable", reason, detail, source}`) — the same discriminated-union safety pattern already proven in P0/P1, just with `Date` converted to an ISO string for portable JSON. Fields: `runId`, `capturedAt`, `ticker`, `canonicalTokenAddress`, `configuredPoolAddress`, `robinhoodAssetStatus`, `robinhoodPrice`, `chainlinkReference`, `oraclePaused`, `secondaryPrice`, `premiumDiscountPct`, `holderConcentration`.

## Design choices directly answering each stated requirement

- **"A temporary Blockscout failure must not invalidate or discard an otherwise valid market snapshot"** — `captureTickerSnapshot` fetches holder concentration in its own try/catch, entirely independent of every other field. `test/captureTickerSnapshot.test.ts` has a dedicated test proving a simulated Blockscout failure leaves `chainlinkReference`, `secondaryPrice`, `premiumDiscountPct`, and `robinhoodPrice` all still `ok`.
- **No fabricated zero** — every field is a `DataPoint`; there is no code path that assigns a bare number when a fetch fails. Tested explicitly for the Robinhood price, Chainlink feed, and holder-concentration failure cases.
- **Partial upstream failure behavior** — tested at both the per-ticker level (one field failing doesn't affect others) and the run level (`test/captureRun.test.ts`: a failed registry fetch, a failed gas sample, or one ticker's total failure each leave every other piece of the run completely intact).
- **Duplicate/retry behavior** — every record carries a `runId` (a fresh UUID per invocation), so two runs' data is always attributable and never ambiguous. `test/captureRun.test.ts` runs `captureRun()` twice against the same directory and asserts both runs' full record sets are present, doubled, with distinct `runId`s — nothing is overwritten. Structurally re-confirmed in this sandbox by actually invoking the CLI twice: 12 ticker lines, 2 distinct run IDs, exit code 0 both times.
- **Supported-ticker invariant** — `test/supportedTickers.test.ts` pins the list to exactly `AAPL, GOOGL, USO, SPCX, TSLA, NVDA`, asserts MSFT/SPY/QQQ/HOOD are excluded, and asserts every entry actually resolves against `CANDIDATE_TICKERS`.
- **Scheduler-safe** — `scripts/captureSnapshot.ts` exits `0` for any completed run, including one with partial upstream failures (that is normal, expected behavior for unattended infrastructure, not something that should page anyone or spam a cron mailbox). It exits `1` only if an unhandled exception escapes `captureRun()` itself — an actual bug, not a routine hiccup. Confirmed structurally: run twice in this sandbox under total network failure (every host blocked), both runs exited `0`, and every field correctly recorded as `unavailable` with a real error message, never a fabricated value.

## What external verification must still confirm before commit

Per explicit instruction, none of the following can be claimed from this sandbox (blocked by the same `host_not_allowed` egress policy documented since P0):

2. Durable persisted records — the three JSONL files actually exist and contain real data after the run.

## Final result — external live verification PASSED (two runs)

Full transcript, as reported by the operator, is preserved in `evidence/p1.2-external-pass-final.txt`. Summary:

- **First run:** registry captured, gas captured, all 6 ticker snapshots written, zero run-level errors. All six supported tickers persisted their verified `configuredPoolAddress` (none null) — confirming the P1.2b correction holds live, not just in local sandbox tests. Robinhood price, Chainlink reference, and secondary-price paths all worked live. Premium/discount correctly came back `unavailable`/stale for every ticker — not a bug, but the existing 48-hour staleness rule correctly firing because the U.S. market was closed for Labor Day and the latest Chainlink references dated from the prior Friday.
- **Second run:** exactly doubled every count (2 gas, 2 registry, 12 ticker snapshots — 16 total), with two fully distinct `runId`s (6 ticker records each), proving durable append behavior and zero overwrite/corruption against real infrastructure, not just the sandbox's synthetic tests.
- **Holder concentration:** succeeded where Blockscout responded; where it didn't, the failure was correctly persisted as `unavailable`/`upstream_error` — never fabricated as zero, confirmed live.

**One real-world calibration observation surfaced by this run, not acted on in this slice:** the 48-hour staleness threshold fired correctly over the long weekend, but an ordinary two-day weekend is already close to 48 hours by itself, and Chainlink's equity feeds have no off-hours heartbeat — so `premium/discount: unavailable` will likely be a frequent, expected weekend state once a dashboard exists, not a rare edge case. Recorded here as a data point for whoever scopes the next slice; no threshold change was made now.
